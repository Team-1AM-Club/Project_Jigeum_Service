# 공공 교통 API키 입력 안내

작성일: 2026-09-16. 이 문서는 입력 방법만 안내하며 실제 키를 기록하지 않는다.

## 입력 위치

저장소의 `backend/.env.transit.local`을 로컬 편집기로 열어 각 `=` 뒤에 발급받은 키를 입력한다. 값에 공백이나 특수문자가 있으면 dotenv 형식에 맞게 따옴표로 감싼다. 키 값은 채팅에 보내지 않고 **“입력 완료”**라고만 알린다.

이 파일은 기존 `.gitignore`의 `.env.*` 규칙으로 제외된다. 루트 및 `backend/.dockerignore`도 로컬 `.env` 파일을 Docker build context에서 제외한다. 기존 `backend/.env`와 사용자 설정은 변경하지 않았다.

현재 `Settings`는 `.env`만 읽고 교통 API키 필드가 없다. **이 입력 파일은 아직 실행 중인 앱과 연결되지 않았다.** 구현 단계에서 정확한 절대 경로를 지정해 로드하고, 실제 운영은 서버 환경변수로 주입한다. 운영 환경변수가 로컬 파일보다 우선한다. 기존 `.env`에 새 필드를 섞어 현재 Pydantic 설정의 알 수 없는 필드 오류를 유발하지 않는다.

## 서비스별 입력 칸

| 환경변수 | 대상 | 입력 형식 |
|---|---|---|
| `SEOUL_SUBWAY_ARRIVAL_API_KEY` | OA-12764 실시간 도착 | 서울 발급 인증키 원문 |
| `SEOUL_SUBWAY_POSITION_API_KEY` | OA-12601 실시간 위치 | 서울 발급 인증키 원문 |
| `SEOUL_SUBWAY_STATIONS_API_KEY` | OA-15442 역 정보 | 서울 발급 인증키 원문; API 제공 방식 검증 전에는 호출에 사용하지 않음 |
| `SEOUL_SUBWAY_TIMETABLE_API_KEY` | OA-101 열차 시간표 | 서울 발급 인증키 원문 |
| `SEOUL_SUBWAY_LAST_TRAIN_API_KEY` | OA-110 막차 시간표 | 서울 발급 인증키 원문 |
| `SEOUL_SUBWAY_PATH_API_KEY` | OA-22724 최단경로 (100178은 소개 페이지) | 서울 열린데이터 인증키 원문; getShtrmPath 사용 권한/인증은 실제 검증 |
| `SEOUL_BUS_STATIONS_API_KEY` | 15000303 정류소 | data.go.kr Decoding 인증키 |
| `SEOUL_BUS_ROUTES_API_KEY` | 15000193 노선 | data.go.kr Decoding 인증키 |
| `SEOUL_BUS_POSITIONS_API_KEY` | 15000332 버스 위치 | data.go.kr Decoding 인증키 |
| `SEOUL_BUS_ARRIVALS_API_KEY` | 15000314 버스 도착 | data.go.kr Decoding 인증키 |

같은 키로 여러 서비스의 이용이 승인되어 있다면 해당 칸에 같은 값을 입력할 수 있다. 키가 같다는 사실만으로 사용 권한이 있다고 판단하지 않는다. 버스 API는 HTTP 클라이언트가 쿼리 파라미터를 한 번 URL Encoding하므로 Encoding된 키를 입력하지 않는다. 키의 `%` 등을 보고 자동으로 추정·변환하지 않는다.

웹시트나 다운로드 자료에는 키 입력 여부와 무관하게 문서에서 확인한 제공 방식을 사용한다. 포털의 서비스 목록 페이지는 별도 데이터셋이 아니므로 입력 칸이 없다. 이 파일을 사용자 입력 중에 다시 생성하거나 덮어쓰지 않는다.

## 검증 시 보호할 정보

키 존재 여부와 서비스 이름만 상태로 출력한다. 키 원문·일부 문자·길이·해시·키가 포함된 URL·환경변수 전체 덤프를 검증 기록에 출력하지 않는다. 서울 API처럼 키가 URL path에 포함되는 경우에도 전체 요청 주소를 로깅하지 않는다. 제공처 오류 원문과 예외 메시지도 그대로 반환하지 않는다.

입력 완료는 실제 서비스 인증 성공을 의미하지 않는다. 사용자는 입력 완료를 알렸지만 OA-101/OA-110/100178의 키 배정에는 혼동 가능성이 있다고 밝혔다. 입력 파일을 읽거나 자동 교환하지 않았다. 해당 서비스의 공식 명세를 확인한 뒤 구현된 검증 도구가 로컬에서 값을 로드해 서비스별 최소 조회를 실행하고 비밀 값 없는 결과만 남겨야 인증 성공으로 판정한다. 인증 실패를 재현하려고 실제 키를 변경하거나 공개하지 않는다. 오류·한도·지연 사례는 합성 응답으로 검증한다.

사용자가 최단경로의 실제 페이지를 OA-22724로 정정했다. 브라우저의 동적 Open API 화면에서 getShtrmPath의 KEY path 인증과 입력/출력 명세를 확인했다. 100178은 소개 페이지로만 유지한다. 로컬 파일은 해당 칸의 서비스 설명 주석만 수정했으며 입력한 키 값은 읽거나 바꾸지 않았다. 서비스별 실제 인증·응답 검증 전에는 권한 성공으로 간주하지 않는다.
