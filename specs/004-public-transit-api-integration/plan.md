**상태**: 설계 문서 작성 완료(조건부) — 외부 데이터 확보·실제 인증/정규화·공동 계약 합의는 구현 선행조건. 구현·인증 호출·테스트·commit 미실행.

## 요약

기본 6개와 추가 4개 서비스의 조회·정규화·실제 호출 검증 → 실제 약속 계획 → 시간표·막차 계획을 순서대로 연결한다. 서울 지하철·버스, 역·정류소 기준 동일 수단 및 양방향 혼합 환승이 전체 범위다. 자료가 부족해 일부만 성공해도 전체 완료로 축소하지 않는다.

공식 서비스 Adapter를 기존 PlaceProvider/RoutingProvider/TransitProvider에 연결한다. ID·단위·운행일·기준시각·조회시각을 보존하고 실제 실패의 Mock 대체를 제거한다. 부족한 버스 미래 운행 및 환승 보행 근거는 확보 선행조건으로 둔다.

### 사용자 결정

- Source.basis_at 변경안 작성 승인. 실제 계약 반영은 공동 개발자 합의 후.
- Safety Buffer는 **첫 승차 전 5분, 여정당 한 번**으로 확정. 정책 버전은 이 결정의 식별자 `transit-initial-5m-v1`로 제안하며 기존 공개 buffer_policy와 공동 정합화한다. 실제 최소 환승 보행·대기시간과 구분하며 도착/탑승 보장값이라고 하지 않는다.
- 사용자 키 입력 완료 진술 확인. 값은 읽지 않았다. OA-101/OA-110/100178의 키가 뒤섞였을 가능성이 있어 서비스 배정·인증은 미검증이다. 자동 교환/무차별 조합 시도는 하지 않는다.

### 추가 사용자 답변

1. 사용자가 최단경로 실제 페이지를 **OA-22724**로 정정했다. 100178은 소개 경로다. 브라우저의 동적 명세에서 **getShtrmPath**, KEY path 인증, 출발역명·도착역명·검색일시 입력, 시간표 포함 Y 기본값을 확인했다. 명세 식별 질문은 해소됐다. 15143842를 자동 대체하지 않는다.
2. 별도 버스 운행표/구간 시간 및 혼합 보행 자료는 **없음**, 추가 자료 조사가 필요하다. 공개 자료를 우선 조사하고 필요한 보완 제공처를 구체적으로 제안한다. 유료 제공처·새 키·인프라는 별도 합의한다.

별도 15000414 혼합 경로는 후보 정보이고 날짜/시각·보행 상세를 해결하지 못한다. 승인 없이 자동 추가하지 않는다. 최신 GTFS 및 실제 보행 근거를 추가 조사했으나 KTDB 2025 평일 하루 GTFS, OA-21208 과거 도보망, OA-21221 과거 환승 집계만으로 현재/미래 각 편과 실제 혼합 보행시간을 충족하지 못했다. 후보별 결손은 research.md에 기록했고 새 자료/API를 자동 채택하지 않았다.

### HTTP와 자료 처리

기존 ProviderClient에 httpx 실제 전송·async 수명주기·업무 코드 해석·서비스별 안전한 오류를 연결한다. HTTP 200 업무 오류도 먼저 해석한다. key는 요청 직전에만 사용하며 URL/params/원문 예외를 로그에 남기지 않는다. 공식 host/path를 서비스별로 확정하고 다른 host로 credential redirect를 허용하지 않는다.

OA-22724는 표 형식과 다른 XML header/body 예제를 제공한다. 전용 업무 코드/구조 검증을 하고 reqHr/wtngHr/totalReqHr·거리 단위, 검색일시 해석, 자정 날짜 및 pagination으로 경로가 잘리지 않는지를 실제 검증한다. 샘플 숫자나 현재 조회시각을 운행 근거로 추정하지 않는다.

공식 문서의 HTTP 주소를 검증 없이 HTTPS 동등 endpoint로 간주하지 않는다. 무키 연결 검증으로 실제 transport를 확인하고 전송 방식이 불명확하면 key 전달 전에 해결한다. 이번 웹 도구의 HTTPS 조회 실패는 제공처의 HTTPS 미지원/장애 증거가 아니다.

JSON/XML은 실제 기능별 포맷을 검증하고 크기/구조를 제한한다. XML DTD/외부 entity를 처리하지 않는다. 구현 시 기존 라이브러리로 안전한 처리가 불가능하면 필요한 의존성을 먼저 제안한다.

ID namespace, WGS84/GRS80, 초/분, 위치/예측/예정시각/실제시각을 구분한다. 검증되지 않은 필드는 계산에 사용하지 않는다. 요청 내 중복 조회를 제거하며 실시간 관측을 다른 요청의 현재 근거로 재사용하지 않는다. 정적/시간표도 개정·적용 조건이 검증된 범위만 사용한다. 자동 전체 수집/주기 작업/새 캐시 인프라는 없다.

### 시간과 호출 예산

설계 상한은 아래와 같다. page 조회와 retry도 HTTP 시도 한 번이다. 실제 계정 한도가 더 낮으면 그 한도가 우선한다. 실제 측정 기간·잔여량을 추정하지 않는다.

| 작업 | 전체 경과시간 상한 | 외부 시도 상한 | 동시 외부 호출 |
|---|---:|---:|---:|
| health/capabilities | 3초 | 0 — 검증 상태 읽기, 요청마다 외부 health 금지 | 0 |
| places | 10초 | 4 | 2 |
| plan/replan | 25초 | 12 | 4 |
| 서비스 최소 실제 검증 1회 | 60.5초 | 2 | 1 |

시도별 wall-clock 상한은 min(30초, 전체 deadline 남은 시간)이다. semaphore 대기·검증·500ms 대기도 전체 예산에 포함한다. httpx read timeout만으로 전체 경과시간을 제한했다고 하지 않는다. Python 3.11 asyncio deadline을 함께 적용한다. 운영자 검증의 60.5초는 30초 × 2 + 500ms 최대치이며 실행 도구는 60초보다 짧은 간격으로 결과를 확인할 수 있어야 한다.

외부 조회별 자동 retry는 연결 실패·timeout·계약상 retryable 일시 장애에만 500ms 후 최대 한 번이다. 인증/권한/한도/입력/잘못된 응답/명시적 nonretryable/예산 부족은 0회다. 502/503/504만 보고 retry 금지를 무시하지 않는다. Adapter·계산 서비스·HTTP transport에 중복 retry를 두지 않는다. 전체 workflow 자동 retry도 없다.

MCP 기존 동일 키/본문 최대 한 번 retry는 보존한다. 성공 재생은 제공처 호출 0회이며 진행 중 중복 요청은 기존 멱등성 조정과 연결한다. 서버의 제공처 retry/예산 소진은 자동 workflow 재실행을 허용하지 않는 결과로 전달한다. 네트워크 응답 유실로 서버 실행이 두 번 시작되는 최악의 경우 외부 시도 상한은 places 8, plan/replan 24다. 이 값은 동일 외부 조회의 4회 retry 허용을 의미하지 않는다. MCP POST 대기는 기존 30초다.

예산 초과는 UPSTREAM_TIMEOUT 등의 기존 오류로 처리하며 검색 중단을 NO_FEASIBLE_JOURNEY로 표시하지 않는다. 제한 확대가 필요하면 공동 계약 합의가 선행한다.

### 약속·막차 계산

목표 도착 = Deadline - 사용자 도착 여유다. 각 승하차·보행·대기를 검증하고 첫 승차 전 5분을 legs/total_duration에 한 번 포함한다. 이미 포함된 Buffer를 표시 단계에서 다시 더하거나 빼지 않는다.

지하철 경로 API는 후보 근거다. 실제 각 편의 시각·운행일·방향·종착지·환승을 검증한다. 버스는 동일 편 대응과 구간 도착 근거가 확인될 때만 계산한다. 혼합 환승에는 통행 가능한 실제 보행 연결/시간을 요구한다.

막차는 검증된 요청 범위의 마지막 연결 여정에서 hard_leave_at와 recommended_leave_at를 구분한다. 후보 3개나 일부 경로를 확인한 것을 전체 범위의 마지막 여정이라고 하지 않는다. 탐색/시간 예산 때문에 완전성을 확인하지 못하면 막차 미지원/실패로 처리한다. 최후 출발 경과, 자정 이후 날짜, 연결 불가, 미지원일, Buffer 부족을 구분한다.

### 공개 계약과 영향 분석

기존 도구/경로/필드 의미를 보존하고 Source.basis_at만 승인된 변경안으로 작성한다. 공동 합의 후 API_SPEC.md·Docs/api/examples.json·Source/응답 스키마·fixture/계약 테스트·MCP JSON schema/표시를 함께 갱신한다.

basis_at=null은 기준시각 미확인이다. retrieved_at로 대체하지 않고 해당 실시간 관측을 현재 운행 검증 근거에서 제외한다. 날짜만 있는 정적/시간표의 개정 기준은 원문/내부 자료와 경고 메시지로 보존하며 임의 자정 timestamp를 만들지 않는다.

공통 client/ProviderResult/정규화 모델 변경은 모든 callers·Mock·예외 처리·테스트에 영향 분석한다. 시간 계산은 실제 caller를 다시 검색하고 헌법 정의를 검증한다. 현재 확인·선택·revision/멱등성의 영향을 받는 계약 정합화도 연동 선행조건이다.

## 3단계 실행 게이트

| 단계 | 범위 | 완료 조건 |
|---|---|---|
| 1. 조회/정규화/실호출 | 설정·로그 보호 → HTTP → 6+4 최소 조회 → ID/단위/시각/범위 기록 | 각 합의 기능 실제 성공 ≥1. 실패/미검증은 다음 계산 근거로 사용하지 않음 |
| 2. 약속 | 계약/확인 점검 → Provider 조립 → Mock fallback 제거 → 실제 계산 | 지하철·버스 및 양방향 혼합 각각 실제 약속 사례, 여유 중복 0 |
| 3. 시간표/막차 | 운행편·날짜·방향·종착지·보행 연결 → 마지막 연결 탐색 → 지원 갱신 | 각 수단·양방향 혼합 실제 막차, 경계 4분류 검증 |

일부 서비스 조회 성공과 계획/막차 성공은 별개다. 미충족 선행조건을 삭제하거나 전체 범위를 축소해 완료로 처리하지 않는다.

## 검증 계획

| 명세 | 검증 |
|---|---|
| SC-001/005/006 | 모든 합의 기능 실제 성공 ≥1, 기본6 각각 정규화 대조, 권한·범위·한도·재현 절차 |
| SC-002/004 | 실제/Demo·기준/조회시각 대조, 합성 secret sentinel로 URL/로그/예외/응답 노출 0 |
| SC-003/010 | 인증·한도·지연·잘못된 응답·빈 결과·미지원 6분류, 허용 retry 1/500ms·금지0, 전체/시도 deadline |
| SC-007 | 지하철·버스 약속 각각 ≥1, 확인→후보, 도착 여유·Buffer 회귀 |
| SC-008 | 지하철·버스 막차 각각 ≥1, 자정 넘김/연결불가/미지원일/Buffer 부족 |
| SC-009 | subway→bus·bus→subway 각각 약속 ≥1·막차 ≥1, 보행/승차 근거, 자료 부족 거부, 주소의 역/정류소 선택 안내 |

실패는 합성 응답으로 재현하며 실키를 변경하거나 한도를 고갈시키지 않는다. 과거 fixture를 현재 조회 성공으로 분류하지 않는다. 기존 테스트 통과와 공개 계약/실제 근거 준수는 별도로 검증한다.

기존 확인·충돌·만료·중복·선택 보호 회귀를 유지한다. 외부 호출은 DB 쓰기 트랜잭션 밖에서 수행하고 적용 직전 만료·revision·멱등성을 재검증한다. 실패/취소는 기존 선택·revision·TTL을 갱신하지 않는다.

## 미충족 선행조건과 설계 후 재점검

- OA-22724 동적 공식 명세의 실제 응답/시간 단위/운행일/경로 완전성 검증 및 보완 자료 확보.
- 사용자 입력 완료한 key의 서비스 배정 및 서비스별 실제 인증·응답·전송 검증.
- 버스 미래 운행/구간 시각, 혼합 보행 근거 확보.
- OA-110/getShtrmPath의 실제 권한·실가동 검증. 숨겨진 종료 안내 문구만으로 서비스를 종료 판정하지 않음.
- basis_at 공동 계약 합의, 영향받는 기존 API 정합성.

Phase 1 후 재점검: MCP 경계, 검증 가능한 코드, 사용자 통제, 비밀 보호 및 범위 보존은 설계에 반영됐다. basis_at의 실제 반영은 공동 합의 게이트로 유지한다. 자료 부족 조건을 성공으로 반환하지 않으므로 헌법 예외는 없다. 보완 자료 및 실제 서비스 검증은 미완료 상태로 남아 전체 기능의 구현/인수 완료를 주장하지 않는다. 기존 명세와 충돌하는 범위 축소 없이 독립적인 Adapter·오류/정규화 작업을 향후 tasks로 분리할 수 있다.
