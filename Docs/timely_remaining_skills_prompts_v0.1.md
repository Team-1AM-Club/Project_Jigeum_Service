# 지금(가칭) — Timely 남은 3개 Skill 생성 프롬프트

> **현재 서비스 개발 방향 — 2026-09-14:** 지금은 **MCP로 제공하는 서비스**다. 별도 제품 화면·설치형 클라이언트를 개발하지 않는다. 본인은 MCP 도구·Hermes 연결·확인/선택 흐름·시연을, 친구는 FastAPI·서비스 Agent·교통 데이터·계산·배포를 담당한다. Hermes + Solar Pro4는 개발·시연용 MCP 클라이언트다. 현재 구현 범위와 완료 기준은 IDEA.md를 따른다.

> **이 문서의 범위:** 아래는 Timely 예선 Skill의 생성·시험·제출용 자산이다. 당시의 Skill 담당 구분과 독립 기능 설명은 보존하며 현재 MCP 개발 분업을 대체하지 않는다. GPS·자동 감시·알림·Calendar·택시 최적화는 현재 MCP MVP의 필수 구현이 아니다. 실제 Skill 원본·새 런타임의 도구·입출력 호환성은 별도로 검증한다.


- **문서 버전:** v0.1
- **작성일:** 2026-08-26
- **목적:** Timely AI 채팅에서 생성할 남은 3개 Skill의 생성 요청문과 테스트 문장을 제공한다.

---

## 사용 방법

각 Skill은 별도 Agent 또는 다른 Skill이 비활성화된 상태에서 생성하고 테스트한다.

1. Timely 중앙 채팅에 해당 Skill의 **생성 프롬프트**를 붙여넣는다.
2. Skill이 생성·활성화되면 **테스트 문장**을 입력한다.
3. 검증되지 않은 교통 정보나 장소를 Agent가 임의로 확정하지 않는지 확인한다.

## 4. 일정별 출발 준비 체크 — `schedule-ready`

### 생성 프롬프트

```text
새 Skill을 만들어줘.

Skill 이름은 영문으로 `schedule-ready`로 해줘.
사용자가 일정 제목, 시각, 장소를 입력하면 이동 준비가 필요한지 판단하고,
출발시각 계산 전에 확정해야 할 정보를 정리하는 Skill이야.

원칙:
- 일정 제목·시각·장소를 확인해 이동 관리가 필요한 일정인지 판단해.
- 장소, 오전/오후, 출발지, 도착 여유시간이 모호하면 최대 3개까지만 질문해.
- 일정이 겹쳐도 임의로 우선순위를 정하지 마.
- 확인되지 않은 이동시간이나 경로를 만들지 마.
- 이미 확인된 정보와 추가 확인할 정보를 구분해.

응답 순서:
1. 이동 관리 필요 여부
2. 확인된 일정 정보
3. 확정해야 할 정보
4. 출발 전 준비사항
5. 다음 행동

생성 후 활성화해줘.
```

### 테스트 문장

```text
내일 오후 2시에 강남역에서 팀플 미팅이 있어.
나는 신림역 근처에 있고 10분 전에 도착하고 싶어.
```

### 통과 기준

- 일정의 시각·장소·출발지·도착 여유시간을 올바르게 정리한다.
- 확인되지 않은 이동시간이나 경로를 만들지 않는다.
- 필요한 정보만 간결하게 추가 질문한다.

## 5. 택시는 어디까지 타야 할까? — `taxi-hybrid`

### 생성 프롬프트

```text
새 Skill을 만들어줘.

Skill 이름은 영문으로 `taxi-hybrid`로 해줘.
이 Skill은 대중교통만으로 Deadline을 지키기 어려울 때,
필요한 구간만 택시를 이용하는 Taxi + Transit 대안을 정리해.

원칙:
- 현재 위치, 목적지, Deadline 또는 막차 제약, 대중교통 정보,
  택시 허용 여부와 최대 비용이 부족하면 최대 3개까지만 질문해.
- 택시를 사용할 수 있다고 사용자가 명시한 경우에만 택시 대안을 제시해.
- 확인되지 않은 택시 요금, 도착시각, 막차 시각을 지어내지 마.
- 택시를 전 구간 타는 방법보다 필요한 구간만 택시를 타는 대안을 우선 검토해.
- 정보가 불충분하면 확정적인 추천 대신 확인 방법을 안내해.

응답 순서:
1. 가장 현실적인 추천안
2. 택시가 필요한 구간
3. 이후 연결할 대중교통 또는 대안
4. 시간·비용 측면의 장단점
5. 추가 확인이 필요한 정보

생성 후 활성화해줘.
```

### 테스트 문장

```text
홍대입구역에서 신림역 근처 집으로 가야 하는데 막차가 애매해.
택시는 탈 수 있지만 최대 1만 원까지만 가능해.
```

### 통과 기준

- 사용자 허용 없이 택시를 권하지 않는다.
- 요금·막차·도착시각을 확인 없이 단정하지 않는다.
- 비용 제한과 필요한 택시 구간을 명확히 구분한다.

## 6. 이 경로, 늦을 위험 있나? — `route-risk-checker`

### 생성 프롬프트

```text
새 Skill을 만들어줘.

Skill 이름은 영문으로 `route-risk-checker`로 해줘.
이 Skill은 사용자가 예정한 이동 경로를 입력하면
환승, 도보, 남은 시간, 도착 여유시간을 기준으로
Deadline을 지키기 어려울 위험을 진단하는 Skill이야.

원칙:
- 출발·도착 예정시각, 환승 횟수, 도보 구간, Deadline,
  현재 시각이 부족하면 최대 3개까지만 질문해.
- 확인되지 않은 지연, 막차, 교통편 운행 여부를 사실처럼 말하지 마.
- 위험도는 낮음, 보통, 높음, 판단 불가 중 하나로 표시해.
- 위험 판단 근거와 적용한 Safety Buffer를 반드시 설명해.
- 위험이 높으면 더 이른 출발 또는 대체 경로 확인을 권하되,
  사용자가 확인하지 않은 구체적 경로를 만들어내지 마.

응답 순서:
1. 위험도
2. 판단 근거
3. 특히 주의할 구간
4. 권장 여유시간 또는 행동
5. 추가 확인이 필요한 정보

생성 후 활성화해줘.
```

### 테스트 문장

```text
18시 20분에 신림역에서 출발해서 19시까지 강남역에 가야 해.
지하철 2호선을 타고 가고, 도보는 약 8분이야.
이 경로로 늦을 위험이 있을까?
```

### 통과 기준

- 위험도를 네 단계 중 하나로 명확히 표시한다.
- 환승·도보·남은 시간을 근거로 위험을 설명한다.
- 실제 교통편 지연이나 운행 여부를 근거 없이 생성하지 않는다.

---

## 공통 점검 항목

- Skill 이름은 영문으로 유지한다.
- Agent는 질문 한 번에 최대 3개의 정보만 요청한다.
- 사용자가 제공하지 않은 장소, 시간, 요금, 교통 정보를 임의로 확정하지 않는다.
- 결론을 먼저 제시하고, 확인된 정보와 불확실한 정보를 구분한다.
