# 지금 — 2인·4일 MCP 개발 분업 계획

- 최초 작성일: 2026-09-12 / MCP 제공 방향 반영: 2026-09-14
- 기준: [IDEA.md](../IDEA.md)의 확정된 2인·4일 MCP 서비스 범위
- 목적: MCP 도구와 기존 계산 백엔드를 통합하고 Hermes에서 전체 이용 흐름을 시연한다.
- 서비스 제공 방식은 MCP로 확정됐다. 시연 이후 별도 제품 화면이나 설치형 클라이언트를 만드는 계획은 없다.
- 이 문서는 구현·테스트·배포 완료 보고서가 아니다.

## 1. 두 사람의 역할

| 담당 | 책임 | 인수 기준 |
|---|---|---|
| 본인: MCP·Hermes·시연 | MCP 도구 5개, 입력 스키마·HTTP 연결, 결과·오류 전달, 조건 확인·후보 선택 흐름, Hermes 연결 설정·설치 안내·시연 | Hermes에서 실제 도구를 호출해 확인된 조건으로 결과를 받고 대안을 선택한다 |
| 친구: 핵심 백엔드 | FastAPI, MainAgent·SubAgent·Skill 통합, 입력 구조화·장소·교통 데이터, 시간 계산·재탐색, 테스트·배포 | 검증된 결과와 출처·기준시각·지원 범위·실패 사유를 API 계약대로 반환한다 |
| 공동 | API·MCP 계약, 문맥·확인·선택 상태의 소유권, 통합 테스트, 지원 범위·제출 자료 | 두 계층이 같은 입력·확인·선택·오류 의미를 유지하며 다른 환경에서 재현된다 |

기존 Skill 개수로 개발 업무를 나누지 않는다. Skill은 내부 실행 자산이고 MCP 도구는 사용자 작업 단위의 외부 인터페이스다.

## 2. 구조와 첫 연결 목표

~~~text
사용자
  ↕ 입력 · 질문 응답 · 조건 확인 · 후보 선택
Hermes + Solar Pro4
  ↕ 로컬 stdio
지금 MCP 서버                    ← 본인
  ↕ 기존 HTTP API
FastAPI + 서비스 Agent·계산      ← 친구
  ↕
검증된 장소·교통 데이터
~~~

MCP 서버는 기존 백엔드를 재사용하는 연결 계층이다. 교통 계산이나 별도 Agent 체계를 중복 구현하지 않는다. FastAPI·Docker·Cloud Run을 유지하고, 로컬 stdio와 원격 HTTP 백엔드의 실행 경계를 구분한다.

첫 테스트는 **Hermes의 Solar Pro4가 get_capabilities를 호출해 MCP를 거쳐 FastAPI 응답을 받는 것**이다. 도구 호출 기록과 실제 응답을 확인한다. 이 연결 테스트만으로 실제 교통 조회까지 완성됐다고 말하지 않는다.

## 3. 도구와 최소 기능

| MCP 도구 | 기존 REST API | 책임 |
|---|---|---|
| get_capabilities | GET /api/v1/capabilities | 지원 범위·기본값·데이터 상태 |
| search_places | GET /api/v1/places | 출발·도착 기준점 후보 검색 |
| interpret_trip | POST /api/v1/mobility/interpret | 이동 조건 구조화·부족 정보 질문 |
| plan_journey | POST /api/v1/journeys/plan | 확인된 조건의 약속·막차 출발 계획 |
| replan_journey | POST /api/v1/journeys/replan | 사용자 요청 대안과 기존 선택 대비 변화 |

상태는 ok, needs_confirmation, unavailable, error를 구분한다. 출처·기준시각·meta.is_demo를 전달하며, 실제 조회 실패를 fixture로 자동 대체하지 않는다.

우선 흐름은 자연어 → 부족 정보 확인 → 최종 조건 확인 → 권장 출발시각·근거 표시 → 재탐색 → 사용자 후보 선택이다. 막차는 첫날 데이터 검증 결과에 따라 노선·운행일·환승 범위를 제한한다.

## 4. 첫날 합의할 계약·데이터

- 기존 API 경로·JSON 필드·오류 의미를 유지한다. 변경이 필요하면 두 사람이 API_SPEC.md와 Docs/api/examples.json을 함께 갱신한다.
- MCP 입력·출력 스키마, 도구 실행 오류와 업무상 unavailable의 매핑을 합의한다.
- ready_for_plan=true는 사용자 동의가 아니다. 확인한 조건·사용자 응답과 계산 요청을 연결하고, 변경된 조건은 다시 확인한다.
- 문맥·선택 Plan·option_id를 어디서 보관하고 언제 폐기하는지 정한다. 다른 대화의 상태를 섞거나 사라진 문맥을 모델이 복원하지 않는다.
- 재탐색 후보 조회는 적용이 아니다. 사용자 선택 전 기존 계획을 덮어쓰지 않는다.
- 모델의 정확한 ID·접근 권한·도구 호출과 백엔드의 별도 AI 호출 설정을 검증한다.
- 키 발급 여부뿐 아니라 실제 장소·교통 응답, 미래 시각 조회, 막차 운행일·방향·종착역·환승 연결, 이용 조건·한도·갱신 주기를 확인한다.
- 데이터 미지원이면 범위를 제한하거나 해당 기능을 보류한다. 확인되지 않은 경로·시각을 모델이 채우지 않는다.

## 5. 4일 일정

| 날짜 | 본인: MCP·Hermes | 친구: 백엔드·데이터 | 공동 확인 |
|---|---|---|---|
| Day 1 | MCP stdio 연결, get_capabilities 호출 | health/capabilities, 장소·교통·막차 API 검증 | 첫 2시간 계약 합의, 첫 4~6시간 지원 범위 확인, Hermes → MCP → FastAPI 응답 |
| Day 2 | 장소·입력 해석·계획 도구, 확인·결과 전달 | 실제 경로·시간 계산, 오류 처리 | 확인된 입력으로 출발시각·근거까지 종단 간 연결 |
| Day 3 | 재탐색·후보 선택·시간 초과·오류 전달, 시연 리허설 | 재탐색·시간 경계·지원 가능한 막차, 서버 안정화 | 사용자 선택·데이터 실패 시나리오 검증. 저녁부터 기능 추가 중단 |
| Day 4 | 다른 환경 설치·Hermes 연결 재현, README·영상 | 치명적 오류 수정, 배포·자격증명·한도 점검 | 실행 방법·설정 예제·테스트 근거·시연 자료 확보 |

매일 최소 두 번 통합한다. 마지막 날 처음 MCP 연결·서버 배포를 시도하지 않는다. 샘플 응답은 개발용으로 표시하고 실제 데이터 경로와 구분한다.

## 6. Skill 활용과 제외 범위

- resolve-trip-details, schedule-ready: 입력 구조화·정보 확인에 필요한 부분.
- leave-by, maginot-line: 시간 정책·설명. 실제 계산·경로 검증은 코드.
- plan-b-recovery, route-risk-checker: 재탐색 비교·위험 근거 설명.
- route-deviation: 수동 재탐색의 사용자 확인 정책만 참고.
- journey-check-in, departure-alert, calendar-conflict, taxi-hybrid, replan-guard의 상태 관리·알림·자동화 기능: 현재 필수 범위에 포함하지 않는다.

원본은 .hermes/skills에서 관리하고 다른 런타임의 호환성을 재검증한다. Timely 대화 테스트를 서비스 연동 완료로 취급하지 않는다.

별도 제품 화면, 설치형 사용자 클라이언트, 영구 이동 이력·회원가입, 진행 상태 버튼·알림, GPS 상시 추적·자동 재탐색, Calendar 자동화, 택시 최적화는 이번 개발 범위에서 제외한다.

## 7. 제출 전 검증

- 다른 환경에서 Hermes가 도구를 발견하고 실제 백엔드 응답을 받는다.
- 모호한 장소·시간만 확인하고, 명확한 19:00 도착 의미를 재질문하지 않는다.
- 계산 전 사용자 동의와 조건 변경 후 재확인, 대안 선택 후 적용을 검증한다.
- 도보·대기·도착 여유·Safety Buffer를 중복 계산하지 않는다.
- 자정 이후 시각·운행일, 지각과 조기 도착 여유 부족을 구분한다.
- 막차 지원 범위를 운행일·방향·종착역·환승 연결 근거로 설명한다.
- 경로 없음·미지원·제공처 실패·시간 초과를 구분하고 거짓 대안을 만들지 않는다.
- 코드·모델·Agent·Skill 실행 근거와 fixture/실제 데이터 구분을 기록한다.
- 설정·로그·영상에 실제 비밀키를 노출하지 않는다.

## 8. 제공·제출 방식

제출물은 MCP 서버 코드, 기존 백엔드·Agent·Skill 실행 자산, 의존성·실행 안내, 비밀값 없는 Hermes 연결 설정, 테스트 결과·시연 영상이다.

Hermes는 첫 검증·시연 대상이며 다른 MCP 클라이언트 호환성을 미리 보장하지 않는다. 주최 측의 원격 MCP 주소·배포 요구를 확인하고 필요하면 인증·연결 방식·배포 범위를 합의한다. 로컬 시연 성공을 원격 제공·대회 제출 요건 충족으로 간주하지 않는다.
