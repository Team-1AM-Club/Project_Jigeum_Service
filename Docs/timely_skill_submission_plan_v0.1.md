# 지금(가칭) — Timely AI 예선 Skill 제출 계획

> **현재 서비스 개발 방향 — 2026-09-14:** 지금은 **MCP로 제공하는 서비스**다. 별도 제품 화면·설치형 클라이언트를 개발하지 않는다. 본인은 MCP 도구·Hermes 연결·확인/선택 흐름·시연을, 친구는 FastAPI·서비스 Agent·교통 데이터·계산·배포를 담당한다. Hermes + Solar Pro4는 개발·시연용 MCP 클라이언트다. 현재 구현 범위와 완료 기준은 IDEA.md를 따른다.

> **이 문서의 범위:** 아래는 Timely 예선 Skill의 생성·시험·제출용 자산이다. 당시의 Skill 담당 구분과 독립 기능 설명은 보존하며 현재 MCP 개발 분업을 대체하지 않는다. GPS·자동 감시·알림·Calendar·택시 최적화는 현재 MCP MVP의 필수 구현이 아니다. 실제 Skill 원본·새 런타임의 도구·입출력 호환성은 별도로 검증한다.


- **문서 버전:** v0.1
- **작성일:** 2026-08-24
- **목적:** Making AI Beneficial Challenge 2026 예선에서 제출할 6개의 Timely AI Agent Skill을 정의한다.
- **전제:** 예선 산출물은 서비스 MVP가 아닌, 일상·업무의 불편을 해결하는 **단일 기능 중심의 AI 에이전트 Skill**이다. 각 Skill은 독립적으로 실행 가능해야 하며, 결선에서는 이들을 `지금` 서비스로 확장·연계한다.

---

## 1. 제출 전략

`지금`의 전체 제품 기능을 하나의 거대한 Agent에 담지 않는다.

대신 사용자가 바로 이해하고 사용할 수 있는 6개의 독립 Skill로 분리한다. 각 Skill은 단독으로 완결된 사용자 가치를 제공하면서도, 모두 다음 문제를 해결한다.

> **사용자가 이동해야 하는 Deadline을 놓치지 않도록, 지금 무엇을 해야 하는지 알려준다.**

### 설계 원칙

- 각 Skill은 하나의 명확한 사용자 질문에 답한다.
- 시간, 환승, 비용, 위험도처럼 정확성이 중요한 값은 근거와 가정을 구분해 제시한다.
- 확인되지 않은 교통 시각이나 경로를 사실처럼 만들어내지 않는다.
- 목적지·시간·이동수단이 모호하면 사용자에게 확인한다.
- GPS 상시 모니터링, Push 알림, 백그라운드 작업, 복잡한 진행 상태 관리는 현재 MCP MVP에서 제외하고 후속 확장으로 남긴다.

## 2. Skill 포트폴리오

| # | Skill | 한 줄 설명 | 사용자 가치 | 우선순위 |
|---:|---|---|---|---|
| 1 | **언제 나가야 해?** | 약속·수업 Deadline에 맞춘 권장 출발시각 계산 | 출발시각을 직접 계산하는 부담을 없앤다. | 필수 |
| 2 | **막차 귀가 마지노선** | 환승까지 고려한 귀가 가능 최종 출발시각 판단 | 막차를 놓칠 불안을 줄인다. | 필수·대표작 후보 |
| 3 | **환승 놓쳤을 때 플랜 B** | 계획이 깨졌을 때 가능한 대안을 우선순위로 제안 | 지연 상황에서 즉시 다음 행동을 정한다. | 필수 |
| 4 | **일정별 출발 준비 체크** | 일정 내용으로 이동 필요 여부와 준비 시각을 정리 | 일정 확인과 이동 준비를 한 번에 돕는다. | 권장 |

| 6 | **이 경로, 늦을 위험 있나?** | 환승·도보·여유시간을 분석해 이동 위험도를 진단 | 출발 전 경로의 취약점을 미리 안다. | 권장 |

## 3. Skill 상세 정의

### 3.1 언제 나가야 해?

#### 사용자 질문

```text
오늘 7시까지 강남역에 가야 하는데 몇 시에 나가야 해?
```

#### 입력

- 출발지
- 목적지
- 도착해야 하는 시각
- 미리 도착하고 싶은 시간
- 예상 이동시간 또는 확인 가능한 경로 정보
- 도보·택시 등 사용자 이동 조건

#### 출력

- 목표 도착시각
- 권장 출발시각
- 이동시간과 적용한 Safety Buffer
- 출발시각을 놓쳤을 때의 예상 위험
- 입력이 모호한 경우의 확인 질문

#### 핵심 차별점

길 자체보다 **언제 출발해야 하는지**를 가장 먼저 알려준다.

---

### 3.2 막차 귀가 마지노선

#### 사용자 질문

```text
지금 여기서 집에 대중교통으로 가려면 언제까지 나가야 해?
```

#### 입력

- 현재 위치 또는 출발지
- 집 또는 귀가 목적지
- 확인 가능한 버스·지하철 경로 및 막차 정보
- 도보 선호
- Taxi 허용 여부와 최대 비용

#### 출력

- 권장 최종 출발시각
- 이론상 가능한 최후 시각(Hard Deadline)
- 마지막으로 연결 가능한 Journey 요약
- 환승·도보에 적용한 Safety Buffer
- 막차가 어려울 경우 가능한 대안

#### 핵심 차별점

특정 역의 막차시간을 알려주는 것이 아니라, **출발부터 환승·도착까지 실제로 연결 가능한 마지막 Journey**를 기준으로 판단한다.

#### 대표작 선정 이유

`지금`의 고유한 문제 정의와 가장 직접적으로 연결되며, 대학생·직장인의 야간 귀가 불편을 분명하게 해결한다.

---

### 3.3 환승 놓쳤을 때 플랜 B

#### 사용자 질문

```text
버스를 놓쳤어. 7시 약속에 아직 갈 수 있을까?
```

#### 입력

- 현재 시각과 현재 위치
- 목적지와 Deadline
- 원래 계획 또는 놓친 교통편
- Taxi 허용 여부와 비용 조건
- 확인 가능한 대체 경로 정보

#### 출력

- Deadline을 지킬 수 있는 대안 우선순위
- 각 대안의 예상 도착시각 및 지각 위험
- 대중교통 유지 / Taxi 혼합 / 지각 예상의 명확한 구분
- 지금 바로 해야 할 행동

#### 핵심 차별점

정상적인 이동을 계속 안내하는 대신, **계획이 실패한 순간에만** 가장 현실적인 다음 행동을 돕는다.

---

### 3.4 일정별 출발 준비 체크

#### 사용자 질문

```text
내일 9시 수업에 늦지 않으려면 뭘 확인해야 해?
```

#### 입력

- 일정 제목·시각·장소
- 출발지
- 도착 전 여유 선호
- 확인 가능한 이동시간 또는 경로 정보

#### 출력

- 일정이 이동 관리 대상인지 판단
- 목적지·시각 등 모호한 정보의 확인 항목
- 목표 도착시각 및 권장 출발시각
- 출발 전 준비 체크리스트

#### 핵심 차별점

일정을 단순 요약하지 않고, **이동을 위해 지금 확정하거나 준비해야 할 정보**를 정리한다.

---

### 3.5 택시는 어디까지 타야 할까?

#### 사용자 질문

```text
막차가 애매한데 택시를 조금만 타면 집에 갈 수 있을까?
```

#### 입력

- 현재 위치와 목적지
- Deadline 또는 막차 제약
- 대중교통 경로 정보
- Taxi 허용 여부
- 최대 Taxi 비용 또는 비용 최소화 선호

#### 출력

- Taxi + Transit Hybrid 후보
- 택시 탑승 구간과 예상 비용
- 이후 이용할 대중교통 연결
- 순수 대중교통·전체 택시 대비 시간/비용 차이
- 가장 균형적인 추천안과 이유

#### 핵심 차별점

택시를 무조건 권하지 않고, **필요한 만큼만 택시를 써서 Deadline을 지키는 방법**을 제시한다.

---

### 3.6 이 경로, 늦을 위험 있나?

#### 사용자 질문

```text
이 경로로 가면 늦을 위험이 있을까?
```

#### 입력

- 예정 Route 또는 Route 요약
- 출발·도착 예정시각
- 환승 횟수와 도보 구간
- 사용자의 도보 및 도착 여유 선호

#### 출력

- 위험도: 낮음 / 보통 / 높음
- 위험 판단 근거
- 추가로 필요한 Safety Buffer
- 특히 주의할 환승·도보 구간
- 더 안전한 출발시각 또는 대체안

#### 핵심 차별점

단순 ETA가 아니라, **경로가 Deadline을 지키기에 얼마나 취약한지**를 설명한다.

## 4. 공통 응답 정책

모든 Skill은 다음 정보를 일관되게 구분한다.

| 구분 | 설명 |
|---|---|
| 확인된 정보 | 사용자가 제공했거나 신뢰 가능한 출처로 확인된 시각·경로·장소 |
| 적용한 가정 | 도보시간, 환승시간, 도착 여유 등 Safety Buffer의 근거 |
| 불확실한 정보 | 실시간 교통 정보, 모호한 장소, 확인되지 않은 막차·운행 정보 |
| 사용자 확인 필요 | 목적지 확정, Taxi 사용, 모호한 오전/오후, 비용 허용 범위 |

### 금지 사항

- 교통편 시각·운행 여부·예상 도착시각을 근거 없이 생성하지 않는다.
- 모호한 장소나 시간대를 임의로 확정하지 않는다.
- Taxi 사용 여부나 비용 허용 범위를 사용자 대신 결정하지 않는다.
- 확인되지 않은 계산 결과를 확정적인 표현으로 안내하지 않는다.

## 6. MCP 서비스 연결 방향

예선 Skill은 실제 원본과 새 런타임 호환성을 검증한 뒤 MCP 서비스의 내부 실행 자산으로 활용한다. 각 Skill을 외부 도구로 일대일 변환하지 않는다.

~~~text
Hermes + Solar Pro4 — 사용자 입력·확인·선택
        ↕
지금 MCP 도구 5개
get_capabilities · search_places · interpret_trip
plan_journey · replan_journey
        ↕
FastAPI → MainAgent → 역할별 SubAgent·Skill
        ↓
검증된 교통 조회·시간 계산·재탐색 코드
~~~

현재 개발은 약속 입력 → 조건 확인 → 계산 결과 → 요청 기반 재탐색 → 후보 선택을 연결한다. 막차는 검증된 범위에서 제공한다. Calendar·GPS·자동 알림·택시 최적화는 예선 개별 Skill의 아이디어가 있어도 현재 필수 구현에 포함하지 않는다.

본인은 MCP 연결과 Hermes 사용 흐름·시연을, 친구는 백엔드·Agent·교통 데이터·계산을 담당한다. 서비스 제공 형태는 MCP이며 상세 범위는 [IDEA.md](../IDEA.md)를 따른다.
