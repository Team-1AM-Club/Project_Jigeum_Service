# 지금 — 친구 담당 추가 Skill 3개 생성 프롬프트

> **현재 서비스 개발 방향 — 2026-09-14:** 지금은 **MCP로 제공하는 서비스**다. 별도 제품 화면·설치형 클라이언트를 개발하지 않는다. 본인은 MCP 도구·Hermes 연결·확인/선택 흐름·시연을, 친구는 FastAPI·서비스 Agent·교통 데이터·계산·배포를 담당한다. Hermes + Solar Pro4는 개발·시연용 MCP 클라이언트다. 현재 구현 범위와 완료 기준은 IDEA.md를 따른다.

> **이 문서의 범위:** 아래는 Timely 예선 Skill의 생성·시험·제출용 자산이다. 당시의 Skill 담당 구분과 독립 기능 설명은 보존하며 현재 MCP 개발 분업을 대체하지 않는다. GPS·자동 감시·알림·Calendar·택시 최적화는 현재 MCP MVP의 필수 구현이 아니다. 실제 Skill 원본·새 런타임의 도구·입출력 호환성은 별도로 검증한다.


- 문서 버전: v0.1
- 담당 범위: 이동 진행 확인 · 경로 이탈 대응 · 재탐색 한도 관리
- 목적: 추가로 제안한 6개 Skill 중 친구 담당 3개를 Timely 채팅으로 생성하고 테스트한다.

## 사용 방법

각 생성 프롬프트를 하나씩 Timely 채팅에 붙여넣는다. 생성 후에는 해당 Skill만 활성화한 새 대화에서 테스트 문장을 입력하고 기대 동작과 비교한다. 아래 문서는 생성 요청문이며, 문서 저장만으로 Timely에 Skill이 등록되지는 않는다.

| Skill | 영문 이름 |
|---|---|
| 이동 진행 확인 | `journey-check-in` |
| 경로 이탈 대응 | `route-deviation` |
| 재탐색 한도 관리 | `replan-guard` |

## 1. 이동 진행 확인 — `journey-check-in`

### 생성 프롬프트

```text
새 Skill을 만들어줘.

이름: journey-check-in
설명: 이동 계획과 사용자의 진행 상황을 대조해 현재 단계와 다음 확인 지점을 안내합니다.

사용자가 “출발했어”, “첫 버스에 탔어”, “도착했어”처럼
진행 상황을 알려주면 Journey의 현재 상태를 정리하는 Skill이야.

아래 절차와 원칙을 SKILL.md 본문에 작성해줘.

입력:
- 사용자가 확정한 이동 계획
- 이전 이동 상태와 마지막 확인 시각
- 사용자의 새로운 진행 상황
- 필요한 경우 현재 위치와 시각

작업 절차:
1. 기존 계획과 마지막으로 확인된 상태를 읽어.
2. 새로운 메시지가 출발, 탑승, 환승, 도착 중 무엇인지 해석해.
3. 정보가 명확하면 해당 상태 변경을 제안해.
4. 다음 확인 지점을 기존 계획에서 찾아 간결하게 안내해.
5. 계획과 다른 이동이나 환승 실패가 확인되면 관련 대응이 필요함을 알려줘.

원칙:
- 사용자의 “이미 출발했어요”, “도착했어요”는 수동 확인으로 반영해.
- “도착한 것 같아”처럼 불명확한 표현은 확정하지 말고 확인해.
- 오래된 메시지가 최신 상태를 되돌리지 않도록 시각을 확인해.
- 실제 위치 도구가 없다면 GPS를 확인했다고 말하지 마.
- 현재 시각만 보고 탑승·출발·도착을 추정하지 마.
- 저장 도구가 없다면 상태는 이번 대화에서 확인한 정보로만 다뤄.
- 정상 이동에는 짧게 답하고 세부 길 안내를 반복하지 마.
- 다른 Skill을 실제 호출하지 않았다면 연결·실행했다고 말하지 마.

응답:
1. 확인된 현재 단계
2. 다음 확인 지점
3. 주의 또는 확인 사항: 필요한 경우에만

Skill 파일을 생성·저장하고 활성화해줘.
```

### 테스트 문장

```text
테스트용 이동 계획은 도보 → 버스 A → 지하철 B → 목적지야.
이전 상태는 출발 전이었고, 지금은 집에서 출발해서 버스 A에 탔어.
```

### 기대 동작

버스 탑승·이동 중으로 정리하고, 다음은 지하철 B로 환승하는 지점이라고 안내해야 한다. 실제 정류장이나 시각을 만들면 안 된다.

## 2. 경로 이탈 대응 — `route-deviation`

### 생성 프롬프트

```text
새 Skill을 만들어줘.

이름: route-deviation
설명: 기존 계획과 다른 이동을 확인하고 현재 위치 기준 재탐색에 대한 사용자 의사를 확인합니다.

사용자가 추천 경로와 다른 교통편을 이용했다고 말하면,
상황을 확인하고 재탐색 여부를 묻는 Skill이야.
대체 경로 생성 자체는 plan-b-recovery의 역할로 남겨줘.

아래 절차와 원칙을 SKILL.md 본문에 작성해줘.

작업 절차:
1. 원래 이동 계획과 현재 이용 중인 교통편·위치를 확인해.
2. 기존 계획과 실제 이동이 다른지 판단해.
3. 이탈이 확인되면 기존 계획의 안내를 그대로 적용하지 마.
4. “현재 위치에서 다시 계산할까요?”라고 사용자에게 물어봐.
5. 승인하면 현재 위치, 시각, 목적지, Deadline, 이동 조건을 정리해
   재탐색에 전달할 요청을 만들어.
6. 거절하면 이번 재탐색 절차를 종료해.

원칙:
- 다른 교통편을 탔다는 사실을 길을 잘못 들었다는 뜻으로 해석하지 마.
- 단일 GPS 좌표나 불확실한 위치만으로 이탈을 확정하지 마.
- 실제 위치 데이터가 없으면 사용자 설명을 근거로 판단해.
- 목적지나 Deadline이 변경됐는지도 필요한 경우 확인해.
- 사용자 승인 전에는 새 경로를 자동 확정하거나 적용하지 마.
- 택시 허용 여부와 비용 조건은 기존 설정을 유지해.
- 실제 모니터링 제어 도구가 없다면 중단했다고 말하지 말고,
  서비스가 처리해야 할 동작으로 표시해.
- 실제 연결 도구가 없으면 재탐색 요청 요약만 반환해.

응답:
1. 상황: 이탈 확인 / 이탈 의심 / 기존 계획과 일치 / 정보 부족
2. 판단 근거
3. 사용자에게 필요한 확인 또는 승인 질문
4. 승인 후 재탐색 요청 요약

Skill 파일을 생성·저장하고 활성화해줘.
```

### 테스트 문장

```text
원래 지하철을 타기로 했는데 지금은 다른 버스에 탔어.
목적지와 약속 시간은 그대로야. 아직 새 경로는 계산하지 마.
```

### 기대 동작

원래 계획과 현재 이동을 확인하고 재탐색 의사를 물어야 한다. 새 경로를 임의로 제시하거나 적용하면 안 된다.

## 3. 재탐색 한도 관리 — `replan-guard`

### 생성 프롬프트

```text
새 Skill을 만들어줘.

이름: replan-guard
설명: 이동 경로의 자동 재제시 횟수를 확인하고 계속 탐색할지 사용자 승인을 요청합니다.

한 번의 탐색 주기에서 사용자에게 새 Journey를
자동으로 최대 3회까지 제시하도록 관리하는 Skill이야.
실제 경로 검색은 다른 Skill이나 서비스가 담당해.

아래 절차와 원칙을 SKILL.md 본문에 작성해줘.

입력:
- 현재 Journey와 탐색 주기 식별자
- 이번 주기에 이미 자동 재제시한 횟수
- 발생한 사건과 중복 확인용 사건 식별자
- 사용자 승인 여부

판단 규칙:
1. 최초 경로 제안은 재탐색 횟수에 포함하지 마.
2. 이번 주기에서 자동 재제시한 횟수가 0~2회이면
   다음 자동 재탐색을 허용할 수 있어.
3. 이미 3회 재제시했다면 네 번째 자동 재제시 전에
   “다른 경로를 계속 찾아볼까요?”라고 확인해.
4. 사용자가 승인하면 새 탐색 주기를 시작하도록 요청해.
5. 거절하면 추가 자동 탐색을 중단하도록 요청해.

횟수 처리:
- 경로 검색을 시작했다는 이유만으로 횟수를 늘리지 마.
- 새로운 Journey가 실제로 사용자에게 제시된 사건에서만 1회 증가시켜.
- 한 번의 응답에 대안 후보가 여러 개 있어도 재제시는 1회로 계산해.
- 네트워크 재시도, API 재시도, 검색 실패는 포함하지 마.
- 같은 사건이 다시 들어오면 중복 증가시키지 마.
- 횟수가 없거나 서로 충돌하면 추정하지 말고 확인을 요청해.

권한과 상태:
- 경로 이탈로 인한 재탐색은 횟수가 남아 있어도 사용자 승인이 먼저야.
- 횟수·중복 확인은 가능하면 명시적인 코드나 저장 상태로 처리해.
- 저장 도구가 없으면 입력된 횟수를 기준으로 판단 결과와
  갱신안을 반환해. 영구 저장이나 주기 초기화를 완료했다고 말하지 마.

응답:
1. 판단: 자동 재탐색 허용 / 사용자 승인 필요 / 중단 / 정보 확인 필요
2. 현재 주기와 재제시 횟수
3. 판단 이유
4. 필요한 질문 또는 상태 갱신안

Skill 파일을 생성·저장하고 활성화해줘.
```

### 테스트 문장

```text
현재 탐색 주기는 cycle-01이고, 자동으로 새 경로를 이미 3회 제시했어.
마지막 경로에서 또 환승을 놓쳤고, 계속 탐색하겠다는 사용자 승인은 없어.
별도로 API 재시도는 2회 있었어. 다음 행동을 판단해줘.
```

### 기대 동작

재제시 횟수는 3회로 유지하고, API 재시도는 제외하며 계속 탐색할지 승인부터 요청해야 한다.
