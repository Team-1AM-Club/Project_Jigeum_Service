# 지금 — 내 담당 추가 Skill 3개 생성 프롬프트

> **현재 서비스 개발 방향 — 2026-09-14:** 지금은 **MCP로 제공하는 서비스**다. 별도 제품 화면·설치형 클라이언트를 개발하지 않는다. 본인은 MCP 도구·Hermes 연결·확인/선택 흐름·시연을, 친구는 FastAPI·서비스 Agent·교통 데이터·계산·배포를 담당한다. Hermes + Solar Pro4는 개발·시연용 MCP 클라이언트다. 현재 구현 범위와 완료 기준은 IDEA.md를 따른다.

> **이 문서의 범위:** 아래는 Timely 예선 Skill의 생성·시험·제출용 자산이다. 당시의 Skill 담당 구분과 독립 기능 설명은 보존하며 현재 MCP 개발 분업을 대체하지 않는다. GPS·자동 감시·알림·Calendar·택시 최적화는 현재 MCP MVP의 필수 구현이 아니다. 실제 Skill 원본·새 런타임의 도구·입출력 호환성은 별도로 검증한다.


- 문서 버전: v0.1
- 담당 범위: 이동 정보 확정 · 일정 충돌 판단 · 출발 알림 판단
- 목적: 추가로 제안한 6개 Skill 중 본인 담당 3개를 Timely 채팅으로 생성하고 테스트한다.

## 사용 방법

각 생성 프롬프트를 하나씩 Timely 채팅에 붙여넣는다. 생성 후에는 해당 Skill만 활성화한 새 대화에서 테스트 문장을 입력하고 기대 동작과 비교한다. 아래 문서는 생성 요청문이며, 문서 저장만으로 Timely에 Skill이 등록되지는 않는다.

| Skill | 영문 이름 |
|---|---|
| 이동 정보 확정 | `resolve-trip-details` |
| 일정 충돌 판단 | `calendar-conflict` |
| 출발 알림 판단 | `departure-alert` |

## 1. 이동 정보 확정 — `resolve-trip-details`

### 생성 프롬프트

```text
새 Skill을 만들어줘.

이름: resolve-trip-details
설명: 모호한 이동 요청에서 장소와 시간을 확인하고 이동 조건을 구조화합니다.

사용자가 “내일 8시 잠실”처럼 불완전한 이동 요청을 입력하면,
계획을 계산하기 전에 정확한 이동 정보를 확정하는 Skill이야.

아래 작업 절차와 원칙은 짧은 description이 아니라
SKILL.md 본문에 작성해줘.

작업 절차:
1. 사용자 입력에서 날짜, 시간, 출발지, 목적지, 출발/도착 의미,
   도착 여유시간, 이동수단을 추출해.
2. 이미 확인된 정보와 모호하거나 누락된 정보를 구분해.
3. 계산에 필요한 확인 질문을 한 번에 최대 3개까지 해.
4. 사용자가 답하면 기존 정보와 합쳐 최종 이동 조건을 정리해.
5. 필수 정보가 확정되면 출발시각 계산에 넘길 수 있는 요약을 만들어.

원칙:
- “8시”의 오전/오후와 출발/도착 의미를 임의로 정하지 마.
- 학교, 지점, 출구, 집 주소처럼 사용자가 말하지 않은 장소를 만들지 마.
- 장소 검색 도구가 없다면 실제 POI를 조회했다고 말하지 마.
- “집”이나 “학교”는 사용자가 제공했거나 실제 저장된 정보로만 해석해.
- 상대 날짜는 기준 날짜와 시간대를 확인할 수 있을 때만 변환해.
- 도착 여유시간은 이동·환승 Safety Buffer와 구분해.
- 이미 명확하게 제공된 정보를 반복해서 질문하지 마.
- 이 Skill에서는 경로 탐색이나 출발시각 계산까지 진행하지 마.

응답:
- 현재 상태: 확인 필요 / 이동 정보 확정
- 확인된 이동 조건
- 필요한 질문: 있을 때만 최대 3개
- 확정 후 다음 단계

Skill 파일을 생성·저장하고 활성화해줘.
```

### 테스트 문장

```text
내일 8시 잠실에 가야 해. 집에서 출발할 거야.
```

### 기대 동작

오전·오후, 잠실의 정확한 장소, 출발지 등을 확인하고 임의로 확정하지 않아야 한다.

## 2. 일정 충돌 판단 — `calendar-conflict`

### 생성 프롬프트

```text
새 Skill을 만들어줘.

이름: calendar-conflict
설명: 여러 일정 사이의 이동시간을 고려해 충돌과 도착 여유 부족을 확인합니다.

두 개 이상의 일정을 연속으로 참석할 수 있는지 판단하는 Skill이야.
단일 일정 준비를 돕는 schedule-ready와 구분해서,
일정 사이의 연결 가능성에 집중해줘.

아래 절차와 원칙을 SKILL.md 본문에 작성해줘.

작업 절차:
1. 각 일정의 날짜, 시작·종료 시각, 장소를 확인해.
2. 일정 사이의 확인된 이동시간과 도착 여유시간을 확인해.
3. 다음 일정의 목표 도착시각을 계산해.
   목표 도착시각 = 다음 일정 시작시각 - 도착 여유시간
4. 앞 일정 종료 후 이동했을 때의 예상 도착시각을 계산해.
   예상 도착시각 = 앞 일정 종료시각 + 확인된 이동시간
   별도로 합의한 추가 여유가 있다면 중복 없이 반영해.
5. 목표 도착시각과 일정 시작시각을 각각 비교해 결과를 알려줘.

판정:
- 연결 가능: 목표 도착시각까지 도착 가능
- 도착 여유 부족: 일정 시작에는 맞지만 목표 도착시각은 넘김
- 일정 충돌: 일정이 겹치거나 다음 일정 시작시각을 넘겨 도착
- 판단 불가: 종료시각, 장소, 이동시간 등 필수 정보가 부족함

원칙:
- 날짜를 포함해 계산하고, 자정을 넘기는 일정도 구분해.
- 이동시간이 없으면 추정하지 말고 확인을 요청해.
- 부족한 정보는 한 번에 최대 3개까지 질문해.
- 사용자 대신 참석할 일정을 선택하거나 취소하지 마.
- 온라인 일정도 사용자가 지정한 접속 장소 조건이 있으면 반영해.
- 캘린더 연결이 없다면 사용자가 입력한 일정으로 판단해.
- 계산은 사용 가능한 계산 도구나 스크립트가 있다면 활용해.

응답:
1. 충돌 판단
2. 충돌하는 일정과 계산 근거
3. 부족한 시간 또는 남는 여유시간
4. 사용자가 선택할 조정안
5. 추가 확인 사항

Skill 파일을 생성·저장하고 활성화해줘.
```

### 테스트 문장

```text
같은 날 수업이 17시 50분에 끝나고 다음 약속은 18시 30분이야.
두 장소 사이 이동시간은 도보 포함 35분이고,
약속에 10분 전에 도착하고 싶어. 추가 여유는 적용하지 마.
```

### 기대 동작

예상 도착은 18:25, 목표 도착은 18:20이므로 정시 참석은 가능하지만 도착 여유가 5분 부족하다고 구분해야 한다.

## 3. 출발 알림 판단 — `departure-alert`

### 생성 프롬프트

```text
새 Skill을 만들어줘.

이름: departure-alert
설명: 권장 출발시각의 변화를 비교해 알림 필요 여부와 안내 문구를 결정합니다.

기존 권장 출발시각이 변경됐을 때,
사용자에게 지금 알려야 할 변화인지 판단하는 Skill이야.

아래 절차와 원칙을 SKILL.md 본문에 작성해줘.

입력:
- 현재 날짜·시각
- 기존 권장 출발시각
- 새로운 권장 출발시각
- 약속 이동인지 막차 이동인지
- 확인된 변경 사유와 위험 상태

작업 절차:
1. 날짜를 포함해 기존·신규 시각을 비교해.
2. 출발시각이 몇 분 당겨졌는지 계산해.
3. 현재부터 기존 권장 출발시각까지 남은 시간을 계산해.
4. 아래 명시된 규칙으로 알림 필요 여부를 결정해.
5. 알림이 필요하면 변경 내용과 다음 행동을 2문장 이내로 작성해.

일반 약속의 시연용 알림 규칙:
- 60분 초과 남음: 10분 이상 당겨지면 알림
- 30분 초과~60분 이하: 5분 이상 당겨지면 알림
- 10분 초과~30분 이하: 3분 이상 당겨지면 알림
- 0분 초과~10분 이하: 2분 이상 당겨지면 알림

별도 처리:
- 출발 전인데 새 권장 출발시각이 현재 또는 과거라면 긴급 알림으로 판단해.
- 막차는 출발시각이 당겨지거나 연결 불가가 확인되면 즉시 알림으로 판단해.
- 변화가 없거나 임계값 미만이면 알림 없음으로 판단해.
- 출발시각이 늦춰졌다는 이유만으로 늦게 나가도 안전하다고 단정하지 마.
- 이미 출발했거나 도착했다면 출발 알림 적용 대상이 아님을 표시해.

원칙:
- 위 숫자는 PRD의 예시를 구체화한 시연용 정책이며 임의 변경하지 마.
- 변경 사유가 없으면 교통 지연 등의 원인을 만들어내지 마.
- 필수 정보가 부족하면 판단을 보류하고 최대 3개까지 질문해.
- 알림 필요 여부와 문구를 반환하는 것이 이 Skill의 역할이야.
- Push나 자동화 도구가 실제 실행되지 않았다면
  “알림을 보냈다” 또는 “예약했다”고 말하지 마.

응답:
1. 판단: 알림 없음 / 일반 알림 / 긴급 알림 / 판단 불가 / 적용 대상 아님
2. 출발시각 변화와 적용 규칙
3. 알림 문구: 필요한 경우에만

Skill 파일을 생성·저장하고 활성화해줘.
```

### 테스트 문장

```text
오늘 현재 시각은 18:00이야.
아직 출발하지 않았고 일반 약속 이동이야.
권장 출발시각이 18:25에서 18:21로 바뀌었어.
변경 사유는 제공되지 않았어. 알림이 필요할까?
```

### 기대 동작

기존 출발까지 25분, 4분 당겨졌으므로 일반 알림이다. 원인은 지어내지 않아야 한다.
